[中文](#cn-v0.1.23) | [English](#en-v0.1.23)

插件 `0.1.23`：支持 DSH `0.2.2-rc.5`。npm 现在把该版本同时放在 `latest` 与 `next` 上。继续支持 `0.2.2-rc.4`、`0.2.2-rc.3`、`0.2.2-rc.2`、`0.2.2-rc.1`、`0.2.2-alpha.3`（`alpha`）及此前已声明版本。

<h3 id="cn-v0.1.23">兼容性更新</h3>

- **显式支持新 RC。** 在 DSH engine、settings peer 与兼容矩阵中加入 `0.2.2-rc.5`。这不是形式更新：`0.1.22` 对 rc.5 只是宽松接纳——门禁靠尾段 `>=0.2.0 <0.3.0` 的预发布匹配放行，node-semver 默认规则为 `false`。显式声明后两种规则都通过，`0.3.0` 仍被拒绝。
- **唯一的升级指南变更不适用本插件。** rc.4 → rc.5 只有一条：基础组合不再固定 `web.searchProvider`，改由 `dsh-web` 按模型提供方路由。本插件不读写该配置、不发网页搜索请求、不产生 `web/deepseek-search-llm-request` 事件。
- **六个直接使用的官方包实质仍是版本更新。** 五个包只有 `package.json` 不同；`dsh-api-remotes` 另有客户端 bundle 与 sourcemap 变化，但两版字节长度完全一致，差异仅 **2 个字节**，位于内联 sourcemap 的位置元数据，运行代码与类型声明未变。
- **无需改动产品代码。** `lib/index.js`、`lib/index.d.ts`、`lib/client.js` 与 npm 上 `0.1.22` 的 tarball 逐字节相同；回复库、快捷发送与折叠偏好无需迁移。
- **dist-tag 变化。** npm 已把 `0.2.2-rc.5` 同时设为 `latest` 与 `next`（此前 `latest` 是 `0.2.2-rc.1`），中英文 README 的标注已同步改写。
- **验证边界。** 覆盖构建、类型检查、101 项测试与 pack dry-run；`dsh --profile web --dump-config` 在 `0.2.2-rc.5` 上退出码 0、stderr 零行。GUI 返回 HTTP 401，未验证真实页面点击发送；未修改 profile 或其他工作区插件。

### 升级

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.23
```

升级后重启 `dsh web` 并刷新页面。

[中文](#cn-v0.1.23) | [English](#en-v0.1.23)

Plugin `0.1.23`: supports DSH `0.2.2-rc.5`, which npm now serves on both `latest` and `next`. `0.2.2-rc.4`, `0.2.2-rc.3`, `0.2.2-rc.2`, `0.2.2-rc.1`, `0.2.2-alpha.3` (`alpha`) and previously declared releases remain supported.

<h3 id="en-v0.1.23">Compatibility update</h3>

- **Explicit support for the new RC.** Add `0.2.2-rc.5` to the DSH engine, settings peer range and compatibility matrix. This is not cosmetic: `0.1.22` only loosely admitted rc.5 — the gate passed it via the `>=0.2.0 <0.3.0` tail under prerelease matching, while node-semver's default rule returned `false`. The explicit entry makes both rules accept it; `0.3.0` stays rejected.
- **The single upgrade guide does not apply here.** rc.4 → rc.5 ships one item: the shipped composition no longer fixes `web.searchProvider` and lets `dsh-web` route by model provider. This plugin never reads or writes that setting, issues no web-search requests and emits no `web/deepseek-search-llm-request` events.
- **The six directly consumed packages are effectively version bumps.** Five differ only in `package.json`; `dsh-api-remotes` also changes its client bundle and sourcemap, but both releases are byte-for-byte the same length and differ by **two bytes** inside inline sourcemap position metadata, with runtime code and declarations unchanged.
- **No product code changes.** `lib/index.js`, `lib/index.d.ts` and `lib/client.js` are byte-identical to the published `0.1.22` tarball; reply storage, quick sending and the fold preference need no migration.
- **Distribution tags moved.** npm now serves `0.2.2-rc.5` on both `latest` and `next` (previously `latest` was `0.2.2-rc.1`); both READMEs were updated to match.
- **Verification limits.** Build, typecheck, 101 tests and pack dry-run pass; `dsh --profile web --dump-config` exits 0 with no stderr on `0.2.2-rc.5`. The GUI returned HTTP 401, so real-page sending was not verified. No profile or other workspace plugin was modified.

### Upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.23
```

Restart `dsh web` afterwards and refresh the page.
