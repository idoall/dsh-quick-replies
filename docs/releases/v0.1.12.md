清掉设置通道里那个已经死掉的 `mode` 字段。行为不变，只是不再假装它还活着。

仍是对最新 DSH `0.2.1-alpha.3` 的兼容声明，同时兼容 `0.2.1-alpha.1`、`0.2.0-rc.2`、`0.2.0-rc.1` 与整条 `0.1.7` 线。

<h3 id="cn-v0.1.12">⚠️ 调整</h3>

- **删掉 `mode`。** DSH `0.2.1-alpha.3` 已从 `ConfigFormSnapshot` 移除该字段，插件读到的一直是 `undefined`——留着它只会让人以为有两条存储路径。契约、两个通道、存储层一起清干净。
- **「内存模式」说法一并退场。** 那条永远走不到的只读提示与其中英文案已删除；设置不可写时统一显示「只读（设置不可写）」。
- **行为没有变化。** 可写判定本来就等价于 `writable === true`，通道选择本来就只看 `status`，所以升级前后完全一致。

### 升级

```sh
dsh plugin --profile web add dsh-quick-replies@latest
```

升级后重启 `dsh web`，刷新页面即可。

[中文](#cn-v0.1.12) | [English](#en-v0.1.12)

Removes the dead `mode` field from the settings channel. Nothing behaves differently; the plugin just stops pretending the field is still there.

Still the same compatibility declaration for DSH `0.2.1-alpha.3`, and still compatible with `0.2.1-alpha.1`, `0.2.0-rc.2`, `0.2.0-rc.1` and the whole `0.1.7` line.

<h3 id="en-v0.1.12">⚠️ Changed</h3>

- **`mode` is gone.** DSH `0.2.1-alpha.3` removed it from `ConfigFormSnapshot`, so the plugin had been reading `undefined` all along — keeping it only suggested a second storage path. The contract, both channels and the store are cleaned up together.
- **The "memory mode" wording retired with it.** The unreachable read-only note and its bilingual string are gone; a library that cannot write now always says "Read-only (settings are not writable)".
- **Nothing behaves differently.** The writable test was already equivalent to `writable === true` and channel selection has always keyed off `status`, so behaviour is identical before and after.

### Upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@latest
```

Restart `dsh web` afterwards and refresh the page.
