适配 DeepSeek Harness `0.2.0-rc.2`：代码零改动，peer 范围加入 `rc.2`，修掉 `0.1.7` 在 `rc.2` 上被门禁跳过的问题。升级无需迁移。

<h3 id="cn-v0.1.8">📦 兼容性</h3>

| 插件版本 | 已验证的 DeepSeek Harness | npm 发布状态 |
| --- | --- | --- |

| `0.1.7` | `0.2.0-rc.1`、整条 `0.1.7` 线 | 已发布（**在 `0.2.0-rc.2` 上会被门禁跳过**） |
| `0.1.6` | `0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2` | 已发布 |

### 为什么发这个版本

`0.1.7` 的上界 `<0.2.0-0` 本意是挡住未经验证的 `rc.2`；`rc.2` 一发布，这条上界就变成了拒载——`0.2.0-rc.2` 既不等于 `0.2.0-rc.1`，也不小于 `0.2.0-0`，整个 bundle 被跳过、快捷栏消失。profile 里仍锁着的 `0.1.6` 反而能装载，只因门禁用 `includePrerelease: true` 比对时 `<0.2.0` 会接纳 `rc.2`。

### ⚠️ 变更

- peer 与 `dsh.engines.dsh` 改为 `>=0.1.7-alpha.2 <0.2.0-0 || 0.2.0-rc.1 || 0.2.0-rc.2 || >=0.2.0 <0.3.0`：新范围的接纳表在 node-semver 默认规则与门禁的 `includePrerelease` 规则下**完全一致**；`0.2.0-rc.3` 等未经验证的预发布仍进不来。
- `dshReleases` 记录 `0.2.0-rc.2`；devDep `@deepseek-ai/dsh-settings` 钉到 `0.2.0-rc.2`；两份 README 同步。业务代码零改动。

### ✅ 核对与实测

- rc.1 → rc.2 逐项核对：`input.dock` 插槽契约目录与 `client/web/src/seed.ts` 模块表**零 diff**；`ctx.configForms`、`settings/document-updated`、`prompt(content, mode, signal, requestId)` 均未变；平台侧唯一实质改动是 `ui-primitives` 的 `Input` 改 `forwardRef`（本插件客户端半边不 import 它）。
- 用 dsh `0.2.0-rc.2` 自带的门禁函数实测**已发布的 0.1.8 tarball**：通过；`0.1.7` 判定不兼容。typecheck 跑在 `0.2.0-rc.2` 类型面上，98/98 测试通过。
- 未做：装进 profile 后的端到端渲染（`--dump-config` 无 skipping、界面显示），留待升级后确认。

### 升级

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.8
```

回复库无需迁移、配置无需改动；升级后**重启 `dsh web`**。

### Why this release exists

`0.1.7`'s upper bound `<0.2.0-0` was meant to keep the untested `rc.2` out; once `rc.2` shipped, that bound became a refusal — `0.2.0-rc.2` is neither equal to `0.2.0-rc.1` nor less than `0.2.0-0`, so the whole bundle is skipped and the bar disappears. A profile still pinned to `0.1.6` keeps loading only because the gate compares with `includePrerelease: true`, under which `<0.2.0` admits `rc.2`.

### ⚠️ Changes

- The peer and `dsh.engines.dsh` ranges become `>=0.1.7-alpha.2 <0.2.0-0 || 0.2.0-rc.1 || 0.2.0-rc.2 || >=0.2.0 <0.3.0`: the new admission table is **identical** under node-semver's default rule and the gate's `includePrerelease` rule; unverified prereleases such as `0.2.0-rc.3` stay out.
- `dshReleases` records `0.2.0-rc.2`; the pinned `@deepseek-ai/dsh-settings` devDependency moves to `0.2.0-rc.2`; both READMEs updated. Zero product-code change.

### ✅ Verified

- Item-by-item rc.1 → rc.2 check: the `input.dock` slot contract directory and the `client/web/src/seed.ts` module table have **zero diff**; `ctx.configForms`, `settings/document-updated` and `prompt(content, mode, signal, requestId)` are unchanged; the only substantive platform change is `ui-primitives`' `Input` becoming `forwardRef`, which this plugin's client half never imports.
- Measured with the gate function dsh `0.2.0-rc.2` itself ships, against the **published 0.1.8 tarball**: passes; `0.1.7` is judged incompatible. Typecheck runs on the `0.2.0-rc.2` type surface, 98/98 tests green.
- Not done: the end-to-end render after installing into the profile (`--dump-config` with no skipping warning, bar visible) — to confirm after upgrading.

### Upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.8
```

No data migration, no config change; **restart `dsh web`** after upgrading.
