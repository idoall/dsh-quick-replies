插件 `0.1.21`：支持 DSH `0.2.2-rc.3`（npm `next`）。同时检查了 `0.2.2-rc.2`，继续支持 `0.2.2-rc.1`（`latest`）、`0.2.2-alpha.3`（`alpha`）及此前已声明版本。

<h3 id="cn-v0.1.21">兼容性更新</h3>

- **显式支持新的 RC 线。** 在 DSH engine、settings peer 与兼容矩阵中加入 `0.2.2-rc.2` 与 `0.2.2-rc.3`；DSH 自带兼容门禁与严格 semver 都接纳这两版，`0.3.0` 仍不在支持范围内。
- **rc.1 → rc.2 改动均不落在插件的消费面上。** 官方客户端 bundle 改为压缩发布并附带 sourcemap 与 `src/`；契约侧新增 `insertQuote` 可选 summary、空提示续跑（`allowEmpty` / `retry`）、`conversation.hero.frame` 槽位、composer `occurrence`、历史分页状态，并移除插件未使用的 `subagent.parentAvailable`。
- **插件使用的接口逐一核对未变。** `settings.configure`、`configForms.get`、`remote.settings` 的 describe/mutate 与 `settings/document-updated`、`sessions.binding/scope`、`prompt` 的 queue/steer 与所用快照字段、五态输入阶段、`composer-blocks.storeFor`、`conversation.input.dock`（list / session / `InputZone`）、`connection.state` 与 `connection/reset` 全部保持原样。
- **rc.2 → rc.3 基本只有版本号。** 六个直接使用的官方包仅 `package.json` 不同，另有 `dsh-api-session-controller` 的 `RemoteErrorDetailsMap` 新增一个错误码，属纯增量。
- **无需改动产品代码。** `lib/index.js`、`lib/index.d.ts`、`lib/client.js` 与 npm 上 `0.1.20` 的 tarball 逐字节相同；回复库、快捷发送与折叠偏好无需迁移。开发依赖只把 settings 对齐到 `0.2.2-rc.3`。
- **验证边界。** 覆盖构建、类型检查、101 项测试与 pack dry-run；`dsh --profile web --dump-config` 在 `0.2.2-rc.3` 上退出码 0、stderr 零行。GUI 返回 HTTP 401，未验证真实页面点击发送；未修改 profile 或其他工作区插件。

### 升级

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.21
```

升级后重启 `dsh web` 并刷新页面。

[中文](#cn-v0.1.21) | [English](#en-v0.1.21)

Plugin `0.1.21`: supports DSH `0.2.2-rc.3` (npm `next`). `0.2.2-rc.2` was checked as well; `0.2.2-rc.1` (`latest`), `0.2.2-alpha.3` (`alpha`) and previously declared releases remain supported.

<h3 id="en-v0.1.21">Compatibility update</h3>

- **Explicit support for the new RC line.** Add `0.2.2-rc.2` and `0.2.2-rc.3` to the DSH engine, settings peer range and compatibility matrix. Both DSH's compatibility gate and strict semver admit them; `0.3.0` remains unsupported.
- **The rc.1 → rc.2 work does not touch this plugin's surfaces.** Official client bundles ship minified with sourcemaps and `src/`; contract additions cover optional quote summaries, empty-prompt continuation (`allowEmpty` / `retry`), a `conversation.hero.frame` slot, composer occurrences and history paging status, while the unused `subagent.parentAvailable` was removed.
- **Every consumed interface was checked and is unchanged.** `settings.configure`, `configForms.get`, `remote.settings` describe/mutate with `settings/document-updated`, `sessions.binding/scope`, `prompt` queue/steer and the snapshot fields used, the five input phases, `composer-blocks.storeFor`, `conversation.input.dock` (list / session / `InputZone`), `connection.state` and `connection/reset` all keep their contracts.
- **rc.2 → rc.3 is essentially version metadata.** The six directly consumed official packages differ only in `package.json`, plus one added error code in `dsh-api-session-controller`'s `RemoteErrorDetailsMap`; purely additive.
- **No product code changes.** `lib/index.js`, `lib/index.d.ts` and `lib/client.js` are byte-identical to the published `0.1.20` tarball; reply storage, quick sending and the fold preference need no migration. Only the settings development dependency moved to `0.2.2-rc.3`.
- **Verification limits.** Build, typecheck, 101 tests and pack dry-run pass; `dsh --profile web --dump-config` exits 0 with no stderr on `0.2.2-rc.3`. The GUI returned HTTP 401, so real-page sending was not verified. No profile or other workspace plugin was modified.

### Upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.21
```

Restart `dsh web` afterwards and refresh the page.
