[中文](#cn-v0.1.18) | [English](#en-v0.1.18)

适配 DSH `0.2.2-alpha.2`，并修复新增 `sending` 输入阶段下的发送判定。

支持 DSH `0.2.2-alpha.2`，继续保留 `0.2.1-rc.4` 及此前已声明版本的兼容性。

<h3 id="cn-v0.1.18">⚠️ 调整</h3>

- **适配新增的 `sending` 输入阶段。** DSH 0.2.2 给 `InputState.phase` 增加了第五个取值 `sending`（普通消息正在等待 Host 接收，编辑器与附件只读）。`0.1.17` 只认识四个旧取值，会把 `sending` 当成「阶段不可观测」而放行；本版把它纳入已知阶段，命中时按 `input-busy` 拒绝，与其余忙碌阶段一致。
- **显式声明最新 alpha。** `0.2.2-alpha.2` 写入 `dsh.engines.dsh`、peer `@deepseek-ai/dsh-settings` 与兼容性矩阵；本版之前只能靠门禁的预发布宽松规则放行（node-semver 严格规则为 false），现在默认 semver 规则也接纳，`0.3.0` 仍在门外（REJECTED）。
- **逐包核对，其余接口完好。** 六个直接消费的官方包中，`dsh-client-ui-settings` 只有 manifest 与 locale 变化；`dsh-settings` 只有一行 `fiber.config` → `fiber.effectiveConfig`；`dsh-api-remotes` 只新增两个前向事件（`settings/document-updated` 仍在）；`dsh-client-connection` 只新增可选 `resolveAsset`；`dsh-api-session-controller` 的 `binding`/`scope`/`prompt` 签名与快照字段未变；`dsh-client-ui-conversation` 的 `conversation.input.dock`、`InputZone`、`input.for(`、`storeFor` 均未动。
- **类型面钉到 `0.2.2-alpha.2`。** `devDependencies` 的 `@deepseek-ai/dsh-settings` 改为 `0.2.2-alpha.2`，同时把 `@deepseek-ai/cordis`、`@deepseek-ai/schemastery` 钉到该运行时使用的 `~4.0.6-alpha.1`、`~3.18.6-alpha.1`，peer 范围相应放宽。98 项测试全部通过。
- **真实 profile 端到端。** `dsh --profile web --dump-config` 在 `0.2.2-alpha.2` 上退出码 0、stderr 零行，`dsh-quick-replies` 行在合成树里。

### 升级

```sh
dsh plugin --profile web add dsh-quick-replies@latest
```

升级后重启 `dsh web`，刷新页面即可。

[中文](#cn-v0.1.18) | [English](#en-v0.1.18)

Adds support for DSH `0.2.2-alpha.2` and fixes the send decision for the new `sending` input phase.

Supports DSH `0.2.2-alpha.2`, while retaining compatibility with `0.2.1-rc.4` and previously declared releases.

<h3 id="en-v0.1.18">⚠️ Changed</h3>

- **Handle the new `sending` input phase.** DSH 0.2.2 adds a fifth `InputState.phase` value, `sending` (an ordinary message waits for the Host to accept it; the editor and attachments are read-only). `0.1.17` only knew the four older values and treated `sending` as "phase unobservable", letting the send proceed; this release recognizes it and refuses with `input-busy`, like every other busy phase.
- **Declare the latest alpha explicitly.** `0.2.2-alpha.2` is added to `dsh.engines.dsh`, the `@deepseek-ai/dsh-settings` peer range and the compatibility matrix. Earlier releases were only admitted by the installer's prerelease leniency (default semver rules said false); now both accept it, and `0.3.0` stays outside (REJECTED).
- **Package-by-package check: the other interfaces are intact.** Of the six directly consumed official packages, `dsh-client-ui-settings` changes only its manifest and locales; `dsh-settings` changes one line (`fiber.config` → `fiber.effectiveConfig`); `dsh-api-remotes` adds two forward events (`settings/document-updated` is still there); `dsh-client-connection` only adds an optional `resolveAsset`; `dsh-api-session-controller` keeps the `binding`/`scope`/`prompt` signatures and snapshot fields; and `dsh-client-ui-conversation` leaves `conversation.input.dock`, `InputZone`, `input.for(` and `storeFor` untouched.
- **Type face pinned to `0.2.2-alpha.2`.** `@deepseek-ai/dsh-settings` moves to `0.2.2-alpha.2` in `devDependencies`, alongside `@deepseek-ai/cordis` and `@deepseek-ai/schemastery` pinned to the runtime's `~4.0.6-alpha.1` and `~3.18.6-alpha.1`; the peer ranges widened to match. All 98 tests pass.
- **Real-profile end to end.** `dsh --profile web --dump-config` exits 0 with zero stderr lines on `0.2.2-alpha.2`, and the `dsh-quick-replies` row is in the composed tree.

### Upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@latest
```

Restart `dsh web` afterwards and refresh the page.
