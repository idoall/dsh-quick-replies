插件 `0.1.22`：支持 DSH `0.2.2-rc.4`（npm `next`）。继续支持 `0.2.2-rc.3`、`0.2.2-rc.2`、`0.2.2-rc.1`（`latest`）、`0.2.2-alpha.3`（`alpha`）及此前已声明版本。

<h3 id="cn-v0.1.22">兼容性更新</h3>

- **显式支持新 RC。** 在 DSH engine、settings peer 与兼容矩阵中加入 `0.2.2-rc.4`。这一点不是形式更新：`0.1.21` 对 rc.4 只是宽松接纳——门禁靠尾段 `>=0.2.0 <0.3.0` 的预发布放行，node-semver 默认规则为 `false`。显式声明后两种规则都接纳，`0.3.0` 仍被拒绝。
- **唯一的升级指南变更不适用本插件。** rc.3 → rc.4 只有一条：DeepSeek 流式内容拒答的错误码 `MALFORMED_RESPONSE` 改为 `CONTENT_REFUSED`，属 `@deepseek-ai/dsh-llm` 层。本插件不发 LLM 请求、不消费 LLM 错误码；插件内部的 `Refusal` 是本地类型（`no-session`、`session-blank` 等），与拒答码无关。
- **六个直接使用的官方包只有包清单变化。** rc.3 → rc.4 全文件比对，运行代码、类型声明与文档逐字节相同，差异仅为 `package.json` 内的版本号与相互依赖版本号。插件消费的槽位、settings、会话、输入阶段与连接接口全部未动。
- **无需改动产品代码。** `lib/index.js`、`lib/index.d.ts`、`lib/client.js` 与 npm 上 `0.1.21` 的 tarball 逐字节相同；回复库、快捷发送与折叠偏好无需迁移。开发依赖只把 settings 对齐到 `0.2.2-rc.4`。
- **验证边界。** 覆盖构建、类型检查、101 项测试与 pack dry-run；`dsh --profile web --dump-config` 在 `0.2.2-rc.4` 上退出码 0、stderr 零行。GUI 返回 HTTP 401，未验证真实页面点击发送；未修改 profile 或其他工作区插件。

### 升级

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.22
```

升级后重启 `dsh web` 并刷新页面。

[中文](#cn-v0.1.22) | [English](#en-v0.1.22)

Plugin `0.1.22`: supports DSH `0.2.2-rc.4` (npm `next`). `0.2.2-rc.3`, `0.2.2-rc.2`, `0.2.2-rc.1` (`latest`), `0.2.2-alpha.3` (`alpha`) and previously declared releases remain supported.

<h3 id="en-v0.1.22">Compatibility update</h3>

- **Explicit support for the new RC.** Add `0.2.2-rc.4` to the DSH engine, settings peer range and compatibility matrix. This is not a cosmetic bump: `0.1.21` only loosely admitted rc.4 — the gate let it through via the `>=0.2.0 <0.3.0` tail under prerelease matching, while node-semver's default rule returned `false`. The explicit entry makes both rules accept it; `0.3.0` stays rejected.
- **The single upgrade guide does not apply here.** rc.3 → rc.4 ships one item: DeepSeek's streamed content-refusal code changes from `MALFORMED_RESPONSE` to `CONTENT_REFUSED`, an `@deepseek-ai/dsh-llm` concern. This plugin sends no LLM requests and consumes no LLM error codes; its own `Refusal` is a local type (`no-session`, `session-blank`, …) unrelated to that code.
- **The six directly consumed official packages differ only in package metadata.** A full file comparison for rc.3 → rc.4 shows byte-identical runtime code, declarations and documentation; only the version and inter-dependency fields inside `package.json` changed. The slots, settings, session, input-phase and connection contracts this plugin consumes are untouched.
- **No product code changes.** `lib/index.js`, `lib/index.d.ts` and `lib/client.js` are byte-identical to the published `0.1.21` tarball; reply storage, quick sending and the fold preference need no migration. Only the settings development dependency moved to `0.2.2-rc.4`.
- **Verification limits.** Build, typecheck, 101 tests and pack dry-run pass; `dsh --profile web --dump-config` exits 0 with no stderr on `0.2.2-rc.4`. The GUI returned HTTP 401, so real-page sending was not verified. No profile or other workspace plugin was modified.

### Upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.22
```

Restart `dsh web` afterwards and refresh the page.
