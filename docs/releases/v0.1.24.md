插件 `0.1.24`：支持 DSH `0.2.3-alpha.2`（npm `alpha`）——首个 0.2.3 线版本，从 `0.2.2-rc.5` 直接跨过来。`latest` 与 `next` 仍是 `0.2.2-rc.5`，继续支持。

<h3 id="cn-v0.1.24">兼容性更新</h3>

- **显式支持 0.2.3 线。** 在 DSH engine、settings peer 与兼容矩阵中加入 `0.2.3-alpha.2`；DSH 门禁与严格 semver 都接纳，`0.3.0` 仍被拒绝。
- **宿主 Node.js 下限提高。** DSH 现在要求 **Node.js 24.x 系列中的 24.22.3+，或 26.13.1+**（不支持 Node 25）。两份 README 的宿主要求已改写；插件自身 `engines.node` 仍是 `>=20`。
- **框架依赖跨小版本。** DSH 的 settings 现在 peer Cordis `~4.2.0-alpha.1` 与 Schemastery `~3.20.0-alpha.1`。开发依赖已对齐 Cordis `4.2.0-alpha.1`、Schemastery `3.20.0-alpha.1`、include / group / loader `1.2.0-alpha.1`；peer 范围追加 `~4.2.0-alpha.1` 与 `~3.20.0-alpha.1`，同时保留旧范围，老 DSH 仍可用。
- **Cordis 4.2 的破坏性改动不涉及本插件。** `ctx.root` 改为 symbol、Service 的 intercept config 改名为 metadata；本插件都未使用。`ctx.inject`、`ctx.effect`、`ctx.get`、`ctx.on`、`ctx.fiber` 签名未变，类型检查在 4.2 下通过。Schemastery 3.20 与 3.19 只有包清单差异，`volatile()` 语义未变。
- **其余指南条目不适用。** `ctx.sessionQuery.inspectSession` 移除、系统提示章节、压缩摘要、CUA、worktree 归档、list_agents 结构、office 技能合并、个性化推荐退役、图片字节上限、PTC 默认 REPL、SDK prompt 时区、Action 卡片等，都与插件的 settings / 槽位 / 发送链路无关。
- **六个直接使用的官方包改动很大，但消费面完好。** session-controller 62 项、conversation 113 项、connection 把浏览器认证重构为可插拔的 `ConnectionAuthentication`；插件使用的 `settings.configure`、`configForms.get`、`remote.settings` 与 `settings/document-updated`、`sessions.binding/scope`、`prompt`、五态输入阶段、`storeFor`、`conversation.input.dock`/`InputZone`、`input.for`、`connection.state`/`connection/reset` 全部未变。
- **无需改动产品代码。** `src/` 未改，`lib/index.js`、`lib/index.d.ts`、`lib/client.js` 与 npm 上 `0.1.23` 的 tarball 逐字节相同；回复库、发送链路与折叠偏好无需迁移。
- **验证边界。** 覆盖构建、类型检查、101 项测试与 pack dry-run；`dsh --profile web --dump-config` 在 `0.2.3-alpha.2` 上退出码 0、stderr 零行。GUI 返回 HTTP 401，未验证真实页面点击发送；未修改 profile 或其他工作区插件。

### 升级

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.24
```

升级后重启 `dsh web` 并刷新页面。

[中文](#cn-v0.1.24) | [English](#en-v0.1.24)

Plugin `0.1.24`: supports DSH `0.2.3-alpha.2` (npm `alpha`) — the first release on the 0.2.3 line, jumped straight from `0.2.2-rc.5`, which remains supported on `latest` and `next`.

<h3 id="en-v0.1.24">Compatibility update</h3>

- **Explicit 0.2.3-line support.** Add `0.2.3-alpha.2` to the DSH engine, settings peer range and compatibility matrix. Both DSH's gate and strict semver admit it; `0.3.0` stays rejected.
- **The host's Node.js floor moved.** DSH now requires **Node.js 24.22.3 or newer in the 24.x line, or 26.13.1 or newer** (Node 25 is unsupported). Both READMEs state this; the plugin's own `engines.node` remains `>=20`.
- **Framework dependencies crossed a minor.** DSH's settings now peers Cordis `~4.2.0-alpha.1` and Schemastery `~3.20.0-alpha.1`. Development dependencies are aligned (Cordis `4.2.0-alpha.1`, Schemastery `3.20.0-alpha.1`, include / group / loader `1.2.0-alpha.1`), and both peer ranges gained `~4.2.0-alpha.1` and `~3.20.0-alpha.1` while keeping the older ranges for older DSH.
- **Cordis 4.2's breaking changes do not apply here.** `ctx.root` became a symbol and Service intercept config became metadata; this plugin uses neither. `ctx.inject`, `ctx.effect`, `ctx.get`, `ctx.on` and `ctx.fiber` keep their signatures and typecheck passes on 4.2. Schemastery 3.20 differs from 3.19 only in its manifest, so `volatile()` is unchanged.
- **The remaining guides do not apply.** `ctx.sessionQuery.inspectSession` removal, system-prompt sections, compaction summaries, CUA, worktree cleanup, the list_agents shape, the office skill merge, the retired recommendations bundle, image byte limits, the PTC REPL default, SDK prompt time zones and action cards are all unrelated to this plugin's settings, slots and send path.
- **The six consumed packages changed a lot, but the consumed surfaces are intact.** Session-controller touched 62 files, conversation 113, and connection reworked browser auth into a pluggable `ConnectionAuthentication`; `settings.configure`, `configForms.get`, `remote.settings` with `settings/document-updated`, `sessions.binding/scope`, `prompt`, the five input phases, `storeFor`, `conversation.input.dock`/`InputZone`, `input.for` and `connection.state`/`connection/reset` are unchanged.
- **No product code changes.** `src/` is untouched, and `lib/index.js`, `lib/index.d.ts` and `lib/client.js` are byte-identical to the published `0.1.23` tarball; reply storage, quick sending and the fold preference need no migration.
- **Verification limits.** Build, typecheck, 101 tests and pack dry-run pass; `dsh --profile web --dump-config` exits 0 with no stderr on `0.2.3-alpha.2`. The GUI returned HTTP 401, so real-page sending was not verified. No profile or other workspace plugin was modified.
