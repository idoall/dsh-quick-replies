Corrects the LAN notes in both READMEs. Docs only — no code changed.

Still the same compatibility declaration for DSH `0.2.1-alpha.3`, and still compatible with `0.2.1-alpha.1`, `0.2.0-rc.2`, `0.2.0-rc.1` and the whole `0.1.7` line.

<h3 id="en-v0.1.11">⚠️ Changed</h3>

- **The LAN notes now say the right thing.** They claimed DSH disables settings persistence on every non-loopback page — that was true up to `0.2.1-alpha.1`; `0.2.1-alpha.3` removed the client-side pin, so a non-loopback page now uses the official settings form like a loopback one. The README now separates the two.
- **The compatibility table gained a row.** Both languages now list `0.1.11` against its DSH version.
- **Nothing behaves differently.** Upgrading changes no behaviour, and your reply library and fold preferences stay where they are.

### Upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@latest
```

Restart `dsh web` afterwards and refresh the page.
