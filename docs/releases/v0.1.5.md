<h3 id="cn-v0.1.5">插件 0.1.5 — 已验证 DeepSeek Harness 0.1.7-rc.1（最新候选版本）</h3>

### 版本对应

| 插件版本 | 已验证的 DeepSeek Harness | npm 发布状态 |
| --- | --- | --- |
| **`0.1.5`** | **`0.1.7-rc.1`（最新 RC）**、`0.1.7-alpha.2` | 本次发布（`latest`） |
| `0.1.4` | `0.1.7-alpha.2` | 已发布 |
| `0.1.3` | `0.1.5-rc.1` | 已发布 |
| `0.1.2` | `0.1.5-rc.1` | 已发布 |
| `0.1.0`–`0.1.1` | `0.1.2-rc.1` | 已发布 |

### 为什么发这个版本

官方发布了 `0.1.7-rc.1`，这是 `0.1.7` 系列的首个候选版本。本版的作用是**确认并声明对新 RC 的支持**——`0.1.7` 线的破坏性变更 `0.1.4` 已经吸收完毕，因此这次没有新的适配工作，只有兼容性确认与遗留清理。三处结论都来自运行实例与官方产物本身，不是推测：

1. **在运行中的 `0.1.7-rc.1` 实例上实测通过。** Host 侧 `Config.listConfigs` 仍把 `dsh-quick-replies` 识别为可配置的表单条目（`status: "schema"`）；客户端 `conversation.input.dock` 的 `quick-replies` occupant 仍为 `active: true`。也就是说宿主半加载、设置表单注册、快捷栏挂载三条链路在 RC 上全部正常。
2. **核对了 rc.1 的实际产物。** `@deepseek-ai/dsh-client-ui-settings` 里 `ctx.configForms` 仍在、`ctx.settingsScope` 仍不存在；`@deepseek-ai/dsh-settings` 里仍没有运行时 `register`。与 `0.1.4` 适配时的判断一致。
3. **官方 rc.1 说明印证了同一批变更。** 发布说明中「设置改由当前 Profile 的插件配置保存；旧 settings.yaml 仅尝试导入一次」与「插件组合包支持多个 patch 和无需重载的配置字段」正是 `0.1.4` 已经适配的模型（命名空间 = loader 条目 id、volatile `Config` 字段、存储落在 profile patch）。

### 改了什么

- **声明记录新 RC。** `dsh.compatibility.dshReleases` 现同时记录 `0.1.7-rc.1` 与 `0.1.7-alpha.2`。
- **peer 范围刻意保持不变。** `dsh.engines.dsh` 与 `peerDependencies['@deepseek-ai/dsh-settings']` 仍是 `>=0.1.7-alpha.2 <0.2.0`：按 node-semver 默认的预发布规则，只要范围里有比较符写了同一个 `major.minor.patch`，该版本的预发布就会被接纳，所以这个范围**同时覆盖** alpha.2 与 rc.1。无需为 RC 放宽范围，也就不会顺带接纳未经测试的版本。
- **清理 `0.1.4` 遗留。** 删除已无调用方的 `assertSectionValid`（宿主半改用 `Config` schema 后，它注释里引用的 Host registration validate hook 在 0.1.7 已不存在）；两处**用户可见**的错误前缀由旧命名空间 `quick-replies:` 改为实际寻址的条目 id `dsh-quick-replies:`——此前遇到冲突时，提示会指向一个在 0.1.7 上已不存在的命名空间。
- **文档强调。** 中英文 README 在顶部与兼容性章节明确标注已支持最新 RC。

### 谁受影响

- **正在使用 `0.1.7-rc.1` 的人**：直接升级即可，本版就是为这个版本发布的。
- **从 `0.1.4` 升级的人**：**回复库无需迁移、配置无需改动**。`0.1.5` 与 `0.1.4` 使用完全相同的存储模型（profile patch 中 `dsh-quick-replies` 条目的 `config`）。
- **仍在更旧 DSH（含 `0.1.6-alpha.2`）的人：请继续用插件 `0.1.3`。** `0.1.5` 声明的宿主要求是 `>=0.1.7-alpha.2 <0.2.0`，低于它的版本未经本轮验证。

### 兼容性与升级

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.5
```

宿主半边只在 DSH 启动时加载，所以**升级后需要重启 `dsh web`**；客户端半边刷新页面即生效。

从 `0.1.4` 升级不需要任何数据操作。若你仍在 `0.1.3` 或更早版本上、且尚未迁移回复库，请先按 [`0.1.4` 的说明](v0.1.4.md)把 `~/.dsh/settings.yaml` 的 `quick-replies.items` 搬到 profile patch 的 `dsh-quick-replies.config.items`。

### 限制

- **快捷栏依赖 DSH 的 `conversation.input.dock` 插槽**：DSH 大改输入区结构后快捷栏可能不再显示；但发送路径只走会话公开的 `prompt`，**不会碰草稿、引用、图片或光标**。
- **回复库属于单个 DSH 实例**：两个独立的 DSH 服务之间不共享。
- **没有权限模型**：能访问该 profile 已鉴权路由的人都能读写回复库。
- **空白会话不发送**：尚无历史消息的新会话会拒绝发送，避免误点「继续」开出一个空会话。
- **发送时机不由本插件决定**：空闲时 `queue`、运行中 `steer`，实际边界由 DSH 决定；插件不 cancel、不 stop，也不会声称「已打断」。

<h3 id="en-v0.1.5">Plugin 0.1.5 — verified against DeepSeek Harness 0.1.7-rc.1 (the latest release candidate)</h3>

### Version matrix

| Plugin version | Verified DeepSeek Harness | npm status |
| --- | --- | --- |
| **`0.1.5`** | **`0.1.7-rc.1` (latest RC)**, `0.1.7-alpha.2` | this release (`latest`) |
| `0.1.4` | `0.1.7-alpha.2` | published |
| `0.1.3` | `0.1.5-rc.1` | published |
| `0.1.2` | `0.1.5-rc.1` | published |
| `0.1.0`–`0.1.1` | `0.1.2-rc.1` | published |

### Why this release exists

The harness published `0.1.7-rc.1`, the first release candidate on the `0.1.7`
line. This release **confirms and declares support for that RC** — `0.1.4`
already absorbed the `0.1.7` breaking changes, so there is no new adaptation
work here, only a compatibility confirmation and some leftover cleanup. All
three findings come from the running instance and the shipped artifacts, not
from inference:

1. **Verified on a running `0.1.7-rc.1` instance.** On the Host,
   `Config.listConfigs` still reports `dsh-quick-replies` as a configurable form
   entry (`status: "schema"`); on the Client, the `quick-replies` occupant of
   `conversation.input.dock` is still `active: true`. Host-half load, settings
   form registration and bar mounting are all intact on the RC.
2. **Checked against the shipped rc.1 artifacts.** In
   `@deepseek-ai/dsh-client-ui-settings`, `ctx.configForms` is still there and
   `ctx.settingsScope` is still absent; `@deepseek-ai/dsh-settings` still has no
   runtime `register`. Exactly what `0.1.4` adapted to.
3. **The official rc.1 notes confirm the same batch of changes.** "Settings are
   now saved through the active Profile's plugin configuration; the old
   settings.yaml is imported at most once" and "plugin composition packages
   support multiple patches and configuration fields that need no reload" are
   the model `0.1.4` already targets (namespace = loader entry id, volatile
   `Config` fields, storage in the profile patch).

### What changed

- **The new RC is recorded.** `dsh.compatibility.dshReleases` now lists both
  `0.1.7-rc.1` and `0.1.7-alpha.2`.
- **The peer range deliberately stays put.** `dsh.engines.dsh` and
  `peerDependencies['@deepseek-ai/dsh-settings']` remain
  `>=0.1.7-alpha.2 <0.2.0`: under node-semver's default prerelease rule a
  prerelease is admitted when some comparator names the same
  `major.minor.patch`, so the range already **covers** both alpha.2 and rc.1.
  Widening it for the RC would also admit versions this plugin never tested.
- **Leftovers from `0.1.4` are cleared.** `assertSectionValid` had no callers
  left once the Host half moved to a `Config` schema, and its doc comment still
  referenced the Host registration validate hook that 0.1.7 removed; it is
  gone. Two **user-visible** error prefixes still said `quick-replies:`, the
  pre-0.1.7 namespace name, so a conflict message pointed at a namespace that
  no longer exists — they now say `dsh-quick-replies:`.
- **Documentation.** Both READMEs state the RC support at the top and in the
  compatibility section.

### Who is affected

- **Anyone on `0.1.7-rc.1`**: upgrade directly; this release exists for that
  version.
- **Upgrading from `0.1.4`**: **no library migration and no config change.**
  `0.1.5` uses the exact same storage model as `0.1.4` (the
  `dsh-quick-replies` entry's `config` in the profile patch).
- **Anyone still on an older DSH, including `0.1.6-alpha.2`: stay on plugin
  `0.1.3`.** `0.1.5` declares its Host requirement as
  `>=0.1.7-alpha.2 <0.2.0` and is not verified below it.

### Compatibility and upgrade

```sh
dsh plugin --profile web add dsh-quick-replies@0.1.5
```

The Host half loads only at DSH boot, so **restart `dsh web`** after upgrading;
the browser half reloads on a page refresh.

Upgrading from `0.1.4` needs no data operation at all. If you are still on
`0.1.3` or earlier and have not migrated yet, follow
[the `0.1.4` notes](v0.1.4.md) to move `quick-replies.items` from
`~/.dsh/settings.yaml` into `dsh-quick-replies.config.items` in the profile
patch.

### Limitations

- **The bar depends on DSH's `conversation.input.dock` slot**: a large change to
  the composer area can stop the bar from appearing. Sending itself only uses
  the Session's public `prompt`, so it **never touches the draft, references,
  images or the caret**.
- **The library is per DSH instance**: two independent DSH servers do not share
  it.
- **No permission model**: anyone who can reach the profile's authenticated
  routes can read and write the library.
- **Blank sessions refuse to send**: a brand-new Session with no history is
  refused, so a resume chip cannot accidentally create an empty conversation.
- **Timing is DSH's decision**: `queue` while idle, `steer` while running, and
  the plugin never cancels, never stops, and never claims it interrupted
  anything.
